## 拍照魔方（watcher 3535）工时/UPPH 计算错误修复（第二十九次）
**问题**：纯拍照魔方人员（如刘玉琼，仅 watcher 数据源）的 UPPH 达 1000+，明显不合理。
**根因**：`efficiency_service.py` 中纯拍照魔方分支把 `work_hours` 算成 `sum(步骤一时长)/3600`（设备累计耗时，刘玉琼仅 0.21h），导致 UPPH=总量/0.21≈1067。
**修复**：
- `config.py` photo_detail widget 增加 `min/max(步骤一完成时间)` 两个 udf 聚合（别名 `步骤一完成时间_first/last`，避免别名冲突），并加 fields 映射 first_time/last_time。
  - 注：widget 3535 的 `步骤一完成时间` = `a1.first_step_complete_dt`（每台步骤一完成时间），正是"第一台→最后一台"的口径。
- `data_sources.py` 新增 `_parse_dt()`；`_normalize_photo_detail_rows` 解析 first_time/last_time 为 datetime 并入行。
- `efficiency_service.py`：
  - 新增模块函数 `_span_hours`(首末跨度，>13:30 剔1h)、`_is_after_lunch_cutoff`、`_spread_hourly`(按工作时段均匀分摊，13点午餐剔除)。
  - watcher 聚合按 (姓名,方式,标准) 累计各组的 min/max 首末时间。
  - 纯拍照魔方分支改为"累计各聚合组首末时间"，循环结束后统一用 `_span_hours` 算工时（兜底标准工作日 7h），并 `_spread_hourly` 填时段表。
**验证**：刘玉琼 首=09:46:18 末=17:17:20 → 跨度7.52h，末>13:30 剔1h → 6.52h；UPPH=223/6.52=34.2，目标245，达标14.0%（mock 端到端测试通过）。
**注意**：沙箱内 godzilla/guanghe 客户端网络不通（get_photo_efficiency 实时调用会超时），故用 mock 跑通纯拍照魔方分支；生产环境刷新接口走真实网络即可生效。拍照魔方目标按用户要求固定 245。

## 首页 HTTP 500 崩溃修复（第三十次）
**现象**：主页（/）打不开，返回 HTTP 500；自动化页/拍照页本身能打开。
**根因**：`index()` 路由（app.py ~945/956 行）汇总三数据源 `staff_list` 时统一取 `s['rate']` 求平均达成率并排序 Top10。但 `_adapt_photo()` 返回的拍照 staff_list 元素**没有 `rate` 字段**（只有 `hourly_comprehensive_rate` 作为达成率主口径、`achievement_rate` 备用、`upph`），遍历到拍照人员即 `KeyError: 'rate'` → 整页 500。根因是之前重写 `_adapt_photo`（加 rank/时段综合达成）时改掉了字段名、首页路由未同步。
**修复**：
- `app.py` `_adapt_photo` 的 staff_list 元素增加 `'rate': hourly_comprehensive_rate`（与 auto/app 统一的达成率口径）。
- `app.py` `index()` 两处 `s['rate']` 改为 `s.get('rate', 0)` 防御（防未来某源缺字段再崩）。
**验证**：test client 返回 200；重启 8080 进程后 /、/automation、/photo 均 200。
**运维注意**：`run_in_background` 启动 app.py 时 cwd 不继承 shell 的 cd，必须用 `cd /c/Users/Administrator/WorkBuddy/2026-07-16-10-31-12/my-dashboard && python app.py`，否则 cwd 落到 workspace 根找不到 app.py。重启前先 taskkill 旧 PID，看门狗可能补拉一个进程导致双监听，需清理成单实例。

## 首页趋势图 Y 轴截断修复（第三十一次）
**现象**："近7天辅助效率达成"折线图中18、19日数据点消失，黄色填充区骤降到0。
**根因**：Chart.js Y 轴写死 `min: 75`，而18/19日实际达成率降至72-74%，全部低于下限→数据被推出画布。
**修复**：`templates/index.html` renderTrend() 中 Y 轴 min 改为自适应（取数据最小值向下取整到5的倍数减5，保底60%）。
**注意**：Flask 模板每次请求实时读取 mtime，改模板不需重启进程，刷新浏览器即生效。
